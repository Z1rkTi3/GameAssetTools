# Mech Generator: параметрический промышленный шагоход

Статус: MVP реализован; проверка самодостаточной публикации выполняется отдельно.
Основной исходный проект — существующий GameAssetTools;
Blender 5.2.0 LTS. Предыдущие модульные, анимационные и художественные задачи
Mech Battler сохраняются. Возможности генератора, нужные для изменения техники,
реализуются до следующей ручной переделки этих моделей; независимые задачи
продолжаются. Готовность инструмента не означает приёмку игрового визуала.

## Текущая основа и границы

`scout_mech` остаётся совместимым примером. Rubin Tower и Watchtower сохраняются.
Используются опубликованные Recipe/Parameter/ComponentSpec, локальные sockets,
`create_mesh`, guarded rebuild, динамические Geometry controls и static GLB export.
Новый рецепт `industrial_walker` входит в тот же плагин. Он не зависит от прежних
незакоммиченных assembly/animated-export дополнений. Core не переписывается.

Единицы — метры и градусы в конфигурации; геометрия Blender Z-up, вперёд −Y.
Корпус строится одной замкнутой сеткой из сечений. Раздельные звенья ног, шарниры
и ступни имеют локальные origins и именованные IN/OUT-крепления. Правая нога
строится тем же алгоритмом с отражёнными координатами без отрицательного scale.
Сложное оружие, новые материалы, control rig и физическая динамика не входят в MVP.
Проверенные старые canonical/native модели игры этим этапом не заменяются.

## MVP и публичные границы

1. Чистый расчёт конструкции в рецепте: размеры корпуса/скосов/креплений,
   длины и толщины звеньев, размеры стоп, углы и симметрия. Зависимые координаты
   вычисляются из этих данных, а не редактируются по отдельности.
2. Именованные крепления одного объявленного стандарта, проверка размеров,
   осей, длины звеньев, допустимого сгиба, достижимости и базовых зазоров.
   Приблизительные COM и опорный многоугольник сопровождаются явными допущениями;
   они не считаются расчётом прочности или гарантией динамической устойчивости.
3. Параметры показываются существующей Geometry-панелью. Небольшое дополнение
   интерфейса добавляет import/export JSON и механический отчёт через тот же рецепт.
   Импорт меняет draft после полной проверки; геометрия меняется обычным Rebuild
   с прежними locks/manual-edit guard. Сохранение presets не переписывает bundle.
4. Повторная генерация сохраняет чужие объекты и не создаёт дубликатов. Ошибочная
   конфигурация отклоняется до изменения сцены.

## Этапы и проверка

- Сохранить baseline SHA/dirty-status и отдельно защитить существующие башни.
- Реализовать рецепт и pure-Python проверки параметров/симметрии/ограничений.
- Проверить BLOCKOUT в настоящем Blender до refinement; показать профиль,
  фронт и перспективу. Изменить корпус, длины ног и углы реальными controls.
- Проверить регистрацию UI, JSON round-trip, Rebuild, отсутствие дубликатов,
  сохранность пользовательского объекта и отказ для защищённого компонента.
- Экспортировать static GLB и повторно импортировать; проверить пакет в изоляции.
- Запустить существующие unittest и Blender workflow/add-on проверки с башнями.

Команды проекта: `python -m unittest discover -s tests -p "test_*.py"` и
`blender --background --factory-startup --python-exit-code 1 --python tests/run_blender_tests.py`.
Адресные проверки основной копии (Blender 5.2.0 LTS):

- `python -B -m unittest discover -s tests -p "test_*.py"` — 99 tests PASS.
- `blender --background --factory-startup --python-exit-code 1 --python tests/blender_mech_generator_test.py`
  — 9 tests PASS: реальные UI controls/JSON/Rebuild, locks, ошибочное сочетание
  допустимых углов, локальные frames при перемещённом/повёрнутом root, симметрия,
  замкнутость и объём сеток, башни, static GLB и повторный Blender import.
- Три настоящих BLOCKOUT-preview (front/right/perspective) просмотрены; это
  технический корпус без оружия и анимационного рига, не принятый игровой мех.
- GLB прочитан Godot 4.7.2 через GLTFDocument: 15 mesh, 15 material surfaces,
  конечные габариты, преобразование Z-up→Y-up и подошва на Y=0; PASS.

Эти тесты не измеряют прочность, динамическую устойчивость или полный поиск
пересечений. Поля `assumptions`/`comApprox` и предупреждение одноногого режима
объясняют пределы оценки. Видимые подъёмы носка не включаются в консервативную
опорную площадку. Углы — авторские геометрические ограничения MVP, не испытанные
пределы реального механизма. Поддерживается только BLOCKOUT.

JSON-команды находятся в **Geometry Presets**. Import меняет поля Geometry,
не сцену: применение проходит обычным Build/Rebuild. Материалы, appearance и
sprites не переносятся из импортируемого geometry preset; различающиеся разделы
перечислены в подробном отчёте как сохранённые. Export сохраняет текущую полную
конфигурацию с неизменными негеометрическими разделами в совместимом формате.
Обычный CLI также принимает её через `--config`.

Корректный JSON-пресет можно загрузить поверх ошибочного draft: проверяется
входящая конфигурация до изменения controls, защита revision остаётся.
На крайних значениях FloatProperty распознаётся только точный float32 round-trip
объявленного min/max. Произвольные значения не обрезаются; JSON/CLI сохраняют
строгие границы. Эти два пограничных сценария проверяются отдельным regression.

## Git и восстановление

Исходно сохранены 13 изменённых tracked-файлов и прежние assembly/export/test
дополнения. Их нельзя включать целиком в MVP-коммит. Перед публикацией проверить
именно HEAD плюс MVP-файлы/хунки в тестовом пакете: зелёный dirty checkout сам
по себе не доказывает работоспособность публикуемой версии.

После успешной проверки — отдельный осмысленный коммит и обычный `git push`
в соответствующую ветку GitHub. Пользователь явно запросил публикацию.
Без force push, удаления чужих изменений и переписывания истории. Отказ сервера
фиксируется как отказ, локальный коммит не считается опубликованным.

Восстановление — только scoped-копии изменяемых исходников с SHA и проверкой
новых пользовательских правок. `reset --hard`, `clean` и замена всего checkout
не используются. План открытый до фактической реализации и проверок.
